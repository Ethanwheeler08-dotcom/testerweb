# SEO &amp; tracking setup

## Per-page meta

Every page has a unique `<title>`, `<meta name="description">`, Open Graph
and Twitter Card tags, favicon links, and the GA4 snippet — all injected
by `scripts/_apply_seo.py`. The page-by-page meta lives at the top of
that script in the `PAGES` dictionary. To change a title or description,
edit that file and re-run:

```bash
python3 scripts/_apply_seo.py
```

The script is idempotent — re-running overwrites the SEO block cleanly
without duplicating tags.

## Sitemap (auto-regenerated)

`sitemap.xml` is generated by `scripts/generate-sitemap.py`. It walks
the repo for `*.html` files (skipping `404.html` and dotted directories
like `.git`) and writes one `<url>` entry per page with `<loc>`,
`<lastmod>` (today's date in UTC), and a simple `<priority>` heuristic.

### How it stays updated when you add a blog post

`.github/workflows/sitemap.yml` runs on every push that touches an
HTML file or the generator itself. The workflow:

1. Checks out the branch
2. Runs `python scripts/generate-sitemap.py`
3. If `sitemap.xml` changed, commits the new version back to the same
   branch with `[skip ci]` in the message (so the workflow doesn't
   re-trigger itself)

So when you add `the-spark/your-new-post.html` and push, the sitemap
is updated automatically in the next commit. No manual step.

You can also run it locally any time:

```bash
SITE_BASE_URL=https://oleo.com.au python3 scripts/generate-sitemap.py
```

### Submitting to Google Search Console

Once `oleo.com.au` is pointed at the live site:

1. Open [Google Search Console](https://search.google.com/search-console)
   and add `oleo.com.au` as a property (domain property is preferred
   over URL-prefix, but either works).
2. Verify ownership. The easiest verification method is the DNS TXT
   record Google gives you — add it via your domain registrar's DNS
   panel.
3. In Search Console, go to **Indexing → Sitemaps**, enter
   `sitemap.xml` (relative to your domain) and click **Submit**.
4. Search Console will fetch `https://oleo.com.au/sitemap.xml` and
   re-check it periodically. Since the workflow above keeps the file
   current, every new post becomes discoverable to Google within a
   day or two of going live.

`robots.txt` already points crawlers at the sitemap, which speeds up
discovery for search engines other than Google as well.

## Open Graph share image

The OG image is `assets/img/og-image.svg` (1200×630, designed). It is
referenced from every page via `og:image` and `twitter:image`. Modern
social platforms (LinkedIn, Twitter, Slack, Discord, iMessage) render
SVG OG images correctly. Facebook prefers raster — if Facebook
preview rendering is important for your launch, export the SVG to a
PNG at the same dimensions and overwrite `assets/img/og-image.png`,
then point the OG tags at the PNG via `scripts/_apply_seo.py`.

## Favicon

`assets/img/favicon.svg` is the primary favicon (modern browsers).
`assets/img/oleo-logo.png` is the legacy PNG fallback and the
apple-touch-icon. Both are linked from every page's `<head>`.

## Google Analytics 4

The GA4 measurement ID `G-HY9WJBL4NY` is wired into every page via
the standard `gtag.js` snippet. No extra setup required — events
start flowing as soon as the site is live and visitors hit a page.

## 404

`/404.html` is a branded not-found page using the same nav, hero,
and footer as the rest of the site. Configure your host to serve it
for unmatched routes:

- **Netlify**: set `not_found = "404.html"` in `_redirects` or rely
  on the default convention (Netlify serves `/404.html` automatically
  for unmatched paths)
- **Vercel / GitHub Pages**: same convention — `/404.html` is served
  automatically for unmatched paths
- **Cloudflare Pages**: same default behaviour

The 404 page has `<meta name="robots" content="noindex">` so it
doesn't show up in search results, and is excluded from the sitemap.
